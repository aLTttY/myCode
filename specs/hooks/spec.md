# 生命周期 Hook Spec

## 背景

MewCode 已具备会话管理、Agent 循环、消息处理、工具执行、权限控制和上下文压缩能力，但生命周期关键节点上的固定工作仍需人工完成。项目需要一套声明式 Hook 机制，在明确时刻自动执行格式化、安全检查、外部通知和上下文注入，同时保持 Agent 主流程稳定。

现有权限规则仅支持精确和 glob 匹配。本功能将统一扩展匹配能力，使权限与 Hook 条件共同支持精确、反向、正则和 glob 匹配。

## 目标

- 用户能够通过“事件 + 可选条件 + 动作”声明自动化规则。
- 生命周期事件覆盖会话、轮次、消息、工具和少量系统节点。
- 工具执行前可根据工具名称及参数作出放行或拒绝决定。
- 重复性的命令、提示词注入和 HTTP 调用能够自动执行。
- Hook 配置和运行错误具有明确边界，不因动作故障中断 Agent 主流程。
- 为后续子 Agent Hook 动作预留兼容入口，但本阶段不实际启动子 Agent。

## 功能需求

- F1: 系统必须从用户级 `~/.mycode/hooks.yaml`、项目级 `.mycode/hooks.yaml` 和本地级 `.mycode/hooks.local.yaml` 加载规则；缺失文件视为空配置。
- F2: 三层规则必须依次按“用户级 → 项目级 → 本地级”合并，同一文件内保持 YAML 声明顺序，不提供显式优先级字段。
- F3: 每条规则必须包含 `event` 和 `action`，可以包含 `if`；条件缺省时无条件触发，每条规则只包含一个动作。
- F4: 系统必须支持 `session_start`、`session_end`、`turn_start`、`turn_end`、`message_received`、`message_sent`、`tool_before`、`tool_after`、`context_compacted` 和 `agent_error` 事件。
- F5: 一轮从完整用户输入被接收开始，到最终答复或停止结果形成结束；内部模型与工具迭代不单独产生轮次事件。
- F6: `message_received` 只对应完整用户输入；`message_sent` 只对应最终 assistant 文本。流式增量、中间工具调用响应和工具结果不重复产生消息事件。
- F7: `tool_before` 在权限判定和工具实际执行之前触发；`tool_after` 在工具成功或失败结果形成后触发，并携带结果状态。
- F8: `session_start` 对新建和恢复会话均触发并标明来源；`session_end` 在可控退出清理期间触发。强制终止等无法清理的情形不保证触发。
- F9: `context_compacted` 只在自动或手动压缩成功后触发；`agent_error` 只覆盖结构化 Agent 错误，不覆盖普通工具失败、权限或 Hook 拦截、取消和迭代上限。Hook 失败不得递归触发 `agent_error`。
- F10: 条件顶层必须且只能选择 `all` 或 `any`；不允许混用或嵌套逻辑组。条件项使用事件字段路径和匹配表达式；字段不存在时该条件项不匹配。
- F11: 匹配语法必须支持兼容旧配置的自动精确/glob 判断、显式 `glob:`、正则 `re:` 和前置 `!` 反向匹配。非法字段、表达式和正则必须在启动时被发现。
- F12: 权限规则必须复用同一匹配能力；冲突顺序保持“会话 > 本地 > 项目 > 用户”，同层采用“精确 > 正则 > glob”，反向匹配继承内部类型优先级，同类型 `deny` 优先，之后按声明顺序。
- F13: 每次事件必须形成版本化 JSON Payload，至少包含事件名、时间、会话和轮次标识、工作区，以及该事件可用的消息、工具、结果、错误或上下文信息。所有动作与条件观察同一份 Payload。
- F14: 系统必须支持 command、prompt、HTTP 和 agent 四类动作；动作仅接受其类型允许的字段，未知或不兼容字段必须被拒绝。
- F15: command 动作必须在工作区根目录执行，通过标准输入接收事件 JSON；命令可配置 0.1–300 秒超时，默认 10 秒。
- F16: HTTP 动作必须把事件 JSON 作为 `application/json` 请求体发送；支持 URL、请求方法和 headers，默认使用 POST，并使用固定 10 秒运行超时。命令、URL 和 headers 不执行事件值模板插入。
- F17: prompt 动作必须把静态内容作为一次性补充指令注入事件后的下一次模型请求，消费后移除，不写入会话历史或持久化日志；`session_end` 禁止使用 prompt 动作。
- F18: agent 动作必须能够被加载和校验，并在触发时记录“尚未实现”，但本阶段不得启动子 Agent。
- F19: `tool_before` 的同步 command 动作以退出码 0 表示放行、退出码 2 表示拒绝，并以标准错误作为拒绝原因；同步 HTTP 动作可返回 allow 或带原因的 deny 决定。prompt 和 agent 动作不能拒绝工具。
- F20: `tool_before` 被拒绝后不得执行工具或后续 `tool_before` 规则；拒绝原因必须转换为失败工具结果回灌模型，使 Agent 可以调整后继续。
- F21: `once: true` 的规则在当前活动会话中最多成功触发一次；条件未命中、同步动作失败或取消不消耗次数，异步动作成功提交即消耗。该状态不持久化，进程重启后重置。
- F22: command 和 HTTP 动作可以后台异步执行；prompt 不允许异步。所有 `tool_before` 动作禁止异步。
- F23: 同步动作按规则顺序执行；异步动作提交后立即继续。`session_end` 不等待已提交的异步动作完成。
- F24: 三层 YAML 必须在启动时集中、整体校验；任一配置存在静态错误时阻止启动且不加载部分规则。
- F25: 已通过校验的 Hook 在运行期发生启动失败、异常、超时、网络错误、非拦截退出码或无效响应时，只记录日志并默认继续 Agent 主流程。

## 非功能需求

- N1: Hook 运行期故障必须与 Agent 主流程隔离；除有效的 `tool_before` deny 决定外，不得改变原有执行结果或停止原因。
- N2: `tool_before` 的条件判断、同步动作和拒绝决定必须在工具执行前完成，不得出现工具已启动后才收到拒绝的竞态。
- N3: 相同配置与相同事件输入必须产生确定的规则匹配顺序和同步执行顺序。
- N4: Hook 配置错误必须指出配置来源、规则位置和失败字段，便于用户定位；错误信息不得输出其他配置中的敏感值。
- N5: command 输出、HTTP 响应、拒绝原因和 Hook 日志必须有大小边界，避免无界内容进入内存、终端或模型上下文。
- N6: 日志不得主动记录 HTTP header 值、完整环境变量或其他已识别的敏感配置；工具参数仅在必要的安全摘要中展示。
- N7: Hook 不得通过模板替换把事件数据隐式拼入命令、URL 或 header；外部动作只能通过统一 JSON Payload 获取动态数据。
- N8: 异步动作必须使用有界资源并在进程清理时停止接收新任务；不得阻止 Agent 继续运行或导致进程无法退出。
- N9: 未配置 Hook 时，现有会话、Agent 循环、消息、上下文、工具、权限和 CLI 行为必须保持兼容。
- N10: 旧权限规则必须继续按原语义加载；新增正则和反向语法不得改变既有精确/glob 规则的判定结果。
- N11: 自动化测试必须覆盖配置分层与校验、全部事件、条件匹配、四类动作、工具拦截、一次性与异步控制、超时、失败隔离和既有功能回归。

## 不做的事

- 本阶段不实际启动或调度子 Agent；agent 动作仅保留配置和触发占位。
- 本阶段不持久化 `once` 状态，不保证跨进程只执行一次。
- 本阶段不提供显式优先级、规则依赖、并行编排或多动作工作流。
- 本阶段不支持 `all`/`any` 的嵌套、混合或任意布尔表达式。
- 本阶段不提供自定义事件、插件事件或 Provider 流式增量事件。
- 本阶段不提供 Hook 配置热重载、管理命令、可视化界面或历史审计存储。
- 本阶段不自动重试失败的 command 或 HTTP 动作。
- 本阶段不把普通 command/HTTP 输出注入模型；只有 prompt 动作和 `tool_before` 拒绝原因可以进入模型上下文。
- 本阶段不允许 `tool_after` 修改既有工具结果，也不允许 Hook 的 allow 决定绕过权限、黑名单或工作区安全检查。
- 本阶段不支持事件数据的字符串模板插值。
- Hook 动作自身不会再次触发生命周期 Hook，避免递归执行。

## 验收标准

- AC1: 三层 Hook 文件含不同规则时全部加载，并按“用户级 → 项目级 → 本地级 → 文件声明顺序”触发；任意文件缺失时系统仍能正常启动。（覆盖 F1、F2）
- AC2: 缺少 event/action、未知事件或字段、非法条件组、非法正则、动作字段缺失/多余、非法执行控制及 `tool_before` 异步配置都会在启动时报告来源和规则位置；三层中任一层无效时系统不加载任何 Hook 并阻止启动。（覆盖 F3、F10、F11、F14、F22、F24）
- AC3: 十种声明事件均可被加载；一个正常交互会话可以观察到对应的会话、轮次、消息、工具和系统事件，且每种事件携带正确的事件名。（覆盖 F4）
- AC4: 一条用户输入经历多次模型—工具迭代时只触发一次 `turn_start` 和一次 `turn_end`；正常完成、取消、错误和迭代上限的 `turn_end` 均包含对应停止原因。（覆盖 F5）
- AC5: 一轮流式答复只对完整用户输入触发一次 `message_received`、对最终 assistant 文本触发一次 `message_sent`；流式增量、中间工具调用响应和工具结果不产生额外消息事件。（覆盖 F6）
- AC6: `tool_before` 在权限判定和工具启动前发生；工具成功、工具自身失败、权限拒绝和 Hook 拒绝均产生一次带相应状态的 `tool_after`。（覆盖 F7）
- AC7: 新会话与恢复会话均触发 `session_start` 且来源正确；正常退出的 `session_end` 在资源关闭前触发并带结束原因。（覆盖 F8）
- AC8: 自动压缩和手动压缩成功后触发 `context_compacted` 并包含压缩前后信息；未压缩或压缩失败不触发。规定范围内的 Agent 错误只触发一次 `agent_error`，普通工具失败、取消、迭代上限和 Hook 失败不触发。（覆盖 F9）
- AC9: `all` 要求全部条件命中，`any` 要求至少一个条件命中；缺失字段不匹配。旧式自动精确/glob、显式 glob、正则和反向表达式对事件字段产生预期结果。（覆盖 F10、F11）
- AC10: 旧权限配置的精确/glob 判定保持不变；新增正则和反向规则可用，并严格遵守层级、匹配类型、deny 及声明顺序的冲突规则。（覆盖 F12）
- AC11: 各事件动作与条件看到同一份 JSON Payload；Payload 版本、时间、会话/轮次、工作区及事件专属数据正确，缺少不适用字段，且可被稳定 JSON 编码。（覆盖 F13）
- AC12: command 在工作区根目录执行并从标准输入读取 Payload；默认超时、合法自定义超时、越界超时配置、正常退出、异常退出和超时行为均符合约定。（覆盖 F14、F15）
- AC13: HTTP 默认以 POST 和 JSON content type 发送 Payload，自定义 method/headers 生效，固定超时可终止无响应请求；事件值不会被插入 URL、命令或 headers。（覆盖 F16）
- AC14: prompt 在下一次模型请求中出现一次，消费后不再出现且不进入会话历史；各事件的立即或排队语义正确，`session_end` 配置 prompt 会在启动校验时失败。（覆盖 F17）
- AC15: agent 动作能够通过配置校验，触发时只记录未实现信息，没有创建新 Provider、Agent、线程或会话。（覆盖 F18）
- AC16: `tool_before` command 返回 0 时继续，返回 2 时工具不执行且 stderr 作为失败工具结果回灌模型；拒绝后剩余前置规则不执行，Agent 可以基于拒绝原因继续下一次迭代。（覆盖 F19、F20）
- AC17: `tool_before` HTTP 返回 allow 时继续进入既有权限流程，返回 deny 时按原因拦截；HTTP 无效响应、网络错误、超时及 command 其他退出码只记录失败并默认放行，且任何 allow 都不能绕过权限或安全检查。（覆盖 F19、F20、F25）
- AC18: `once: true` 的同步规则成功后在同一活动会话不再执行；条件未命中、失败或取消后仍可重试；异步动作成功提交即不再提交。重启并恢复同一会话后规则可以再次触发。（覆盖 F21）
- AC19: 同步规则严格按合并顺序执行；command/HTTP 异步动作提交后主流程立即继续；`tool_before` 不存在异步路径，`session_end` 不等待已提交任务。（覆盖 F2、F22、F23）
- AC20: command 启动失败、异常、超时、HTTP 错误和 agent 占位均不会改变 Agent 主流程；日志与拒绝内容遵守大小边界，并且不泄露 headers、完整环境或测试敏感标记。（覆盖 F25、N1、N4–N8）
- AC21: 未提供任何 Hook 文件时，既有会话恢复、普通聊天、Plan/Do 模式、工具执行、权限、上下文压缩、Skill、MCP 和 CLI 退出行为通过回归测试。（覆盖 N9、N10）
- AC22: 端到端场景配置格式化 command、上下文 prompt、通知 HTTP 和危险命令拦截规则：用户发起任务后，command 自动运行、prompt 仅注入一次、HTTP 收到正确 Payload、危险工具调用被拒绝并回灌、Agent 调整后继续完成，Hook 故障不终止会话。（覆盖 F1–F25、N1–N11）
