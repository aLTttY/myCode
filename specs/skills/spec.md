# MyCode Skill 系统 Spec

## 背景

MyCode 已具备统一斜杠命令、工具目录、分层系统提示、上下文管理和会话重建能力，也预留了“已激活 Skill”提示位置，但目前没有 Skill 的发现、解析、按需加载、隔离执行或工具收窄机制。用户执行重复性 AI 工作时，仍需反复输入相同提示词。

本功能把可复用的 AI 操作封装为带元信息的 Markdown Skill。系统启动时只暴露有效 Skill 的名称和一句说明，避免把全部 SOP 和工具定义提前塞入上下文；模型或用户选择 Skill 后，再加载完整指令和所需工具。

现有固定 `/review` 命令将迁移为内置 `review` Skill，并保留 `/rev` 兼容入口。

## 目标

- 支持项目级、用户级和内置三级 Skill，按明确优先级选择有效定义。
- 通过两阶段加载降低启动上下文占用，并提高模型发现和选择 Skill 的准确率。
- 将激活后的完整 SOP 持续置于高优先级环境上下文，支持多个共享 Skill 同时激活。
- 支持共享当前对话和一次性独立对话两种执行模式。
- 使用 Skill 工具白名单收窄模型可见工具，同时保留既有权限和安全边界。
- 支持文件型与目录型 Skill、参数安全绑定、斜杠短命令和热更新。
- 提供可直接使用和覆盖的 `commit`、`review`、`test` 三个内置样板。

## 功能需求

### Skill 发现与定义

- F1：系统从项目级 `.mycode/skills/`、用户级 `~/.mycode/skills/` 和内置资源中发现 Skill，优先级依次为“项目 > 用户 > 内置”。同名时只保留最高优先级的有效定义。
- F2：系统支持两种能力包：
  - 单文件 Skill：任意 `*.md` 文件。
  - 目录型 Skill：目录内以 `SKILL.md` 为入口，并可携带专属工具定义、实现脚本及其他资源。
- F3：入口 Markdown 必须由 YAML frontmatter 和非空 Markdown 正文组成。正文是发给模型执行的 SOP。
- F4：frontmatter 描述唯一名称、非空单行说明、可见工具白名单、执行模式、独立模式历史轮数，以及可选模型。名称必须能够安全注册为斜杠命令。
- F5：共享模式不得指定模型；独立模式的历史轮数必须是非负整数，表示携带最近 N 个完整对话轮次，`0` 表示不携带历史。
- F6：单个文件存在 YAML、字段、正文或目录包解析错误时，系统跳过该 Skill、显示来源明确且不泄露正文的警告，并继续加载其他 Skill。无效的高优先级定义不阻止同名低优先级有效定义生效。
- F7：同一层级出现多个同名有效 Skill 时，因无法确定覆盖关系，启动立即失败并指出冲突来源。
- F8：有效 Skill 名称若与现有非 Skill 斜杠命令的规范名或别名冲突，启动立即失败。`commit`、`review`、`test` 属于 Skill 命名空间；`/rev` 始终指向当前生效的 `review` Skill。
- F9：完成优先级合并后，系统验证所有生效 Skill 的工具白名单。任何名称无法对应内置工具、已发现的 MCP 工具或该目录型 Skill 的专属工具时，启动立即失败。
- F10：Skill 正文可使用 `{{input}}` 引用调用参数。系统必须把参数作为 user 级数据安全绑定，不得把原始用户内容提升为系统级指令；没有占位符时，参数仍作为独立 Skill 输入传入。

### 两阶段加载与激活

- F11：每轮构建模型请求时，系统只为未加载 Skill 提供当前生效的名称和一句说明，不注入完整正文或专属工具定义。热更新后，下一轮目录摘要同步变化。
- F12：系统提供内置 `load_skill` 工具。模型可按名称加载 Skill；用户也可通过自动注册的斜杠命令直接触发同一加载流程。
- F13：`load_skill` 是系统级工具，任何 Skill 白名单都不能隐藏或禁用它；未知名称、失效定义和加载失败必须返回可恢复的结构化错误。
- F14：共享 Skill 首次加载后进入当前会话的激活集合。完整静态 SOP 在每次模型请求和每次 Agent 迭代重建时都置于醒目的高优先级环境上下文；重复加载同一 Skill 不产生重复副本。
- F15：多个共享 Skill 可以同时激活，按首次激活顺序稳定呈现。再次调用已激活 Skill 时，只增加本次 user 级输入，不改变原有顺序。
- F16：共享 Skill 的调用、助手回复、工具调用和工具结果都保留在主对话历史中。共享 Skill 一直激活到 `/new` 创建新会话，或因删除、非法热更新而被停用；`/clear` 只清终端，不影响激活状态。
- F17：至少一个共享 Skill 激活后，模型可见业务工具是所有已激活 Skill 白名单的并集；未激活任何 Skill 时保持现有完整工具集。Plan Mode、权限系统和安全规则仍可进一步限制或拒绝工具，`load_skill` 始终保留。
- F18：目录型 Skill 的专属工具定义只在该 Skill 实际加载后提供给模型。共享模式下，它们随 Skill 保持可用；Skill 停用或会话重建后移除。

### 独立执行

- F19：独立 Skill 每次调用都创建一次性独立对话，只激活本次选中的 Skill，不继承主会话中其他已激活 Skill 的 SOP 或工具集合。
- F20：独立对话携带当前调用输入，以及配置指定的最近 N 个完整主对话轮次。复制时不得拆散助手工具调用与对应工具结果，也不复制主会话系统提示。
- F21：独立对话只获得该 Skill 白名单内的业务工具及 `load_skill`；沿用现有权限、安全、取消和 Agent 迭代限制。声明模型时使用该模型，否则沿用主会话模型。
- F22：独立对话结束后立即销毁其上下文和激活状态。主历史只保留本次 Skill 调用和最终结果摘要，不写入独立对话的中间消息、工具调用或工具结果。
- F23：Skill 参数通过 `{{input}}` 绑定到本次调用的 user 级输入；共享模式进入主历史，独立模式进入独立历史。原始斜杠文本不作为模型消息保存。

### 斜杠命令与热更新

- F24：每个当前生效的 Skill 自动注册为 `/<name> [input]`。命令帮助和 Tab 补全展示名称、说明及执行模式；项目或用户覆盖同名 Skill 时，命令自动指向最高优先级有效定义。
- F25：调用 Skill 斜杠命令时，系统按其元信息选择共享或独立流程。Skill 命令的原始文本不进入模型历史，参数按 user 级 Skill 输入传递。
- F26：`/help` 同时展示固定命令和当前生效的 Skill 命令；`/help <skill>` 显示来源、说明、执行模式、历史轮数和可选模型，但不展示完整 SOP、工具实现或其他敏感内容。
- F27：现有固定 `/review` 提示命令迁移为内置 `review` Skill；`/review` 和兼容别名 `/rev` 均调用当前优先级生效的 `review` Skill。
- F28：系统在每次处理新用户输入或斜杠命令前检查 Skill 资源变化，不依赖进程重启或常驻文件监听。
- F29：新增、修改或优先级变化的有效 Skill 在下一轮更新目录摘要、帮助、补全、命令路由、SOP 和专属工具。已激活共享 Skill 的有效内容修改在下一轮直接生效。
- F30：已激活 Skill 被删除、变为非法或被改变为独立模式时，系统立即停用它并显示警告。即使同名低优先级定义重新成为有效候选，也不自动激活；用户必须重新调用。
- F31：运行期间新出现的单个非法 Skill、同层重名或未知白名单工具不得破坏当前交互进程；系统拒绝有问题的定义、显示安全错误，并继续应用其余合法更新，保持目录、命令、提示和工具状态一致。
- F32：非法 Skill 修复后自动重新进入目录和命令列表，但不会自动激活。

### 内置样板

- F33：系统随安装包提供 `commit`、`review`、`test` 三个可直接执行的内置 Skill；项目级和用户级可以按正常优先级覆盖它们。
- F34：`commit` 样板使用共享模式，检查当前改动、形成合适的提交说明、执行必要验证并在权限允许时创建一次提交。
- F35：`review` 样板使用独立模式且默认不携带历史，以只读方式检查当前未提交改动，只报告缺陷、回归、安全问题和测试缺口，并把结果摘要回流主对话。
- F36：`test` 样板使用共享模式，识别并运行与当前项目和用户输入相关的测试，报告实际结果；未经 SOP 明确要求不修改产品代码。

## 非功能需求

- N1：Skill 发现、同层冲突判断、优先级覆盖、目录摘要、激活顺序和工具集合必须确定；相同文件状态产生相同结果。
- N2：启动阶段只能把生效 Skill 的名称和一句说明加入模型上下文，不得提前注入完整 SOP、专属工具 schema、实现脚本或被覆盖定义。
- N3：完整激活指令必须在每次请求和 Agent 迭代中重建，不能被历史压缩移除；上下文摘要不得改写 Skill SOP。
- N4：热更新必须以一致的目录快照生效。单个非法定义不得造成命令目录、提示目录和工具目录彼此不一致，也不得让其他合法更新只应用一部分。
- N5：Skill 白名单只控制模型的工具可见性，不代表权限授予。工具执行仍须经过既有参数校验、工作区边界、危险操作限制、权限模式和人工审批。
- N6：所有目录型 Skill 实现脚本默认按有副作用工具处理，不因 schema 声明而绕过审批；执行须受现有超时和输出大小限制，错误不得泄露环境变量、凭据或完整敏感参数。
- N7：`load_skill` 的系统级豁免只保证其始终可见，不允许它代替业务工具执行任意文件、命令或网络操作。
- N8：参数绑定必须保持角色边界。用户输入、斜杠参数以及独立执行回流内容不能被拼接为系统级指令。
- N9：独立执行不得污染主对话的系统提示、激活集合或中间历史；在工作区产生的已授权文件和命令副作用仍然真实保留。
- N10：复制历史时必须保持 Provider 合法消息顺序，不得产生孤立工具结果、缺失工具调用或被截断的完整轮次。
- N11：独立上下文可临时加载共享 Skill，但不得递归启动另一个独立上下文；嵌套尝试返回可恢复错误。
- N12：Skill 指定模型沿用当前 Provider 和凭据。模型不可用或请求失败时，应安全结束本次独立执行并向主对话回流失败摘要，不损坏主会话。
- N13：新增能力必须兼容现有 Provider、MCP、上下文压缩、会话日志、权限模式、Plan Mode、取消和流式输出行为。
- N14：`/clear` 继续只清终端；`/new` 在创建新会话时清除全部共享 Skill 激活状态和对应专属工具。
- N15：自动化测试必须覆盖三级覆盖、两种能力包、解析隔离、启动校验、两阶段加载、共享与独立执行、历史边界、参数安全、白名单组合、专属工具、命令注册、热更新、会话清理和三个内置样板。

## 不做的事

- 本阶段不实现 Skill 市场、远程分发、安装、升级、版本约束、依赖解析、签名或信任评分。
- 不跨会话或跨进程持久化激活状态；恢复历史会话时 Skill 仍从未激活状态开始。
- 不提供 Skill 启用/禁用配置、手工卸载界面、独立管理面板或图形界面。
- 不支持用户自定义 Skill 斜杠别名；仅保留内置兼容别名 `/rev`。
- 不允许共享模式 Skill 指定模型，也不新增多 Provider 凭据路由或自动模型发现。
- 不支持独立模式递归启动独立模式。
- 不为目录型 Skill 自动安装 Python 包、系统命令或其他运行时依赖。
- 不新增容器或操作系统级强隔离；专属工具沿用当前权限和安全模型。
- 不改变现有长期记忆提取策略，也不把 Skill 正文自动写入长期记忆。
- 不实现 Skill 使用统计、质量评分、遥测或推荐排序。

## 验收标准

- AC1：分别在项目、用户和内置层放置同名 Skill，只加载项目定义；移除项目定义后用户定义生效，再移除用户定义后内置定义生效。
- AC2：项目层同名文件解析失败时，该文件产生警告且用户层有效定义继续生效；其他合法 Skill 不受影响。
- AC3：单文件 Markdown 与包含 `SKILL.md`、工具 schema 和实现脚本的目录包都能被发现；缺失入口、非法 YAML、缺少必填字段、空正文、非法模式、非法历史轮数及共享模式声明模型时，仅对应 Skill 被跳过并产生安全警告。
- AC4：同一层存在两个同名有效 Skill 时，程序在进入交互前失败并指出两处来源；Skill 名与固定命令或别名冲突时同样启动失败。
- AC5：生效 Skill 白名单引用不存在的内置、MCP 或专属工具时启动失败；依赖的 MCP 未成功发现时也视为工具不存在。合法白名单不影响 `load_skill` 可见性。
- AC6：首次模型请求中可以观察到全部生效 Skill 的名称和一句说明，但看不到完整正文、专属工具定义、被覆盖定义或实现脚本内容。
- AC7：模型调用 `load_skill` 后，下一次 Agent 迭代可以看到完整 SOP 和对应工具；加载未知、已失效或损坏的 Skill 返回结构化错误，Agent Loop 可继续。
- AC8：依次加载两个共享 Skill 后，每次请求及每次 Agent 迭代都按首次激活顺序包含两份完整 SOP；重复加载不会重复注入，执行上下文压缩后 SOP 仍完整存在。
- AC9：共享 Skill 的输入、回复、工具调用和结果进入主历史；`/clear` 后仍保持激活，`/new` 后激活集合和专属工具均为空。
- AC10：未激活 Skill 时模型获得现有完整工具集；激活多个共享 Skill 后只获得其白名单并集及 `load_skill`。切换 Plan Mode 后有副作用工具仍被移除，权限拒绝仍然生效。
- AC11：目录型 Skill 未加载时，其专属工具 schema 不发送给模型；加载后按白名单出现。停用或新建会话后消失。执行脚本时会进入有副作用审批，并正确处理拒绝、超时、超量输出和安全错误。
- AC12：独立 Skill 配置 `history: 0` 时只收到本次输入；配置 `history: 2` 时收到最近两个完整轮次。含工具调用的轮次不会被拆开，主系统提示和其他已激活 Skill 的 SOP 不会被复制。
- AC13：独立 Skill 未指定模型时使用主会话模型；指定模型时使用同一 Provider 下的指定模型。模型不可用或请求失败时，主会话收到失败摘要且仍可继续交互。
- AC14：独立执行完成后，主历史只新增可识别的 Skill 调用和最终摘要；独立对话的中间回复、工具调用和工具结果均不出现，下一次调用也无法看到上次独立上下文。
- AC15：独立对话内加载共享 Skill 时，该 Skill 仅在外层独立执行期间可见；尝试加载另一个独立 Skill 返回可恢复错误，不创建嵌套对话。
- AC16：包含普通文本、换行、Markdown 和类似系统指令内容的参数通过 `{{input}}` 传入后始终保持 user 角色；正文多次引用得到同一输入，没有占位符时输入仍可被 Skill 使用。
- AC17：每个生效 Skill 都能通过 `/<name> [input]` 调用，并出现在 `/help` 与 Tab 补全中；帮助只显示安全元信息。项目覆盖内置 Skill 后命令立即指向项目定义。
- AC18：`/review` 与 `/rev` 都调用当前生效的 `review` Skill；原始斜杠文本不进入模型历史。其他固定命令和别名继续保持现有行为。
- AC19：运行期间新增 Skill 后，下一次输入即可在目录、帮助和补全中看到；修改有效 Skill 的说明、SOP、白名单、专属工具或优先级后，下一轮使用新定义，无需重启。
- AC20：已激活 Skill 被删除、改坏或改为独立模式后，下一轮立即停用并警告；恢复合法后重新出现在目录，但必须由用户或模型重新加载。
- AC21：热更新时引入非法文件、同层重名或未知工具，只拒绝有问题的定义并保持目录、命令、提示和工具快照一致；其他合法更新仍生效，交互进程继续运行。
- AC22：内置 `commit` 能检查改动、形成提交说明、运行必要验证，并仅在权限允许时创建提交；被拒绝时安全停止且不声称已提交。
- AC23：内置 `review` 在独立只读上下文审查未提交改动，主历史只收到问题摘要，工作区无新增修改。
- AC24：内置 `test` 能识别并运行相关测试、报告真实命令结果；没有明确修复要求时不修改产品代码。
- AC25：端到端共享场景中，用户执行 `/commit <要求>`，系统加载共享 SOP、收窄工具、保留执行历史；随后加载另一个共享 Skill 时工具集合按并集变化，`/new` 后全部清空。
- AC26：端到端独立场景中，用户在已有历史和共享 Skill 的主会话执行 `/review`，独立上下文仅携带规定历史和 review 工具，结束后只回流摘要，主会话原有共享 Skill 状态不变。
- AC27：自动化测试覆盖全部功能需求与非功能边界，现有 Provider、MCP、权限、上下文、会话、命令和 Agent 测试继续通过。
