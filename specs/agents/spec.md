# MewCode 子 Agent 委派 Spec

## 背景

MewCode 已具备主 Agent 循环、工具系统、分层权限、上下文管理，以及一次性独立 Skill 执行能力，但尚未提供通用的子任务委派机制。主 Agent 无法通过一个稳定工具，在预定义角色与父对话 Fork 两种模式间选择；独立执行也缺少完整的后台生命周期、权限状态隔离、结果回流和资源限制。

本功能要让子任务在独立运行时中执行，避免其消息和工具轨迹污染主对话，同时复用现有 LLM、Hook、文件系统等基础设施。定义式 Agent 从固定角色和空白对话开始；Fork 式 Agent 复用父请求前缀以提高 prompt cache 命中率。

## 目标

- 通过一个 schema 稳定的 `Agent` 工具支持定义式和 Fork 式委派。
- 支持从 Markdown + YAML frontmatter 加载多来源角色，并按固定优先级覆盖。
- 隔离父子 Agent 的消息、权限授权、文件读取缓存和 Token 统计。
- 共享 LLM 客户端、Hook 引擎和工作区文件系统等基础设施。
- 让子 Agent 非交互地持续运行，直至自然完成、失败、取消或达到限制。
- 支持同步返回和后台执行，并把后台结果安全送回主对话。
- 通过多层工具限制、不可覆盖的嵌套禁令和资源上限控制风险。
- 保持 Fork 首次请求的父前缀与工具定义稳定，以利用 prompt cache。

## 功能需求

- F1：系统必须始终向主 Agent 提供 schema 稳定的 `Agent` 工具，通过 `type` 参数选择定义式或 Fork 式委派。`prompt` 必填；定义式必须指定角色，Fork 禁止指定角色并强制后台执行。
- F2：定义式 Agent 必须从空白消息历史和角色固定系统提示开始，不继承父对话；Fork 式 Agent 必须继承触发工具调用前的完整父请求快照，并在末尾追加子任务 user 消息。
- F3：Fork 快照必须保留父请求的 system prompt、消息、当前用户请求、工具定义及工具顺序，不包含父 Assistant 正在生成的内容和本次 `Agent` 工具调用；Fork 创建后父子状态完全分离。
- F4：角色必须用 Markdown 与 YAML frontmatter 定义。frontmatter 包含名称、用途说明、工具白名单、工具黑名单、模型档位、最大轮次和权限模式；正文作为伴随整个生命周期的系统提示。
- F5：角色来源包括项目、用户、内置及外部注入的插件目录，优先级固定为“项目 > 用户 > 内置 > 插件”。插件同名定义按注册顺序由先注册者胜出并产生诊断。
- F6：角色必须在启动时加载，并在每次主请求前检查热更新。非法定义只产生诊断；运行中的子 Agent 固定使用创建时快照，新任务使用最新有效定义。
- F7：角色模型支持 `inherit`、`haiku`、`sonnet`、`opus` 档位。非继承档位由应用配置映射到当前 Provider 的具体模型 ID；缺少所需映射的角色定义无效并产生诊断。
- F8：父子 Agent 必须隔离消息历史、临时权限授权、文件读取缓存和 Token 统计；子 Agent 不继承父会话临时批准。
- F9：子 Agent 必须复用同一进程中的 LLM 客户端、Hook 引擎和工作区文件系统；本阶段不提供独立 Worktree。
- F10：子 Agent 必须以非交互“跑到底”方式执行；模型不再请求工具即为自然完成，也可能因达到最大轮次、失败或取消而结束。
- F11：子 Agent 遇到需要人工批准的工具调用时不得弹出审批，而应收到结构化拒绝并继续决定是否改用其他方案。角色权限模式只允许 `inherit`、`default`、`strict`，不得配置绕过模式。
- F12：工具限制必须依次应用不可覆盖的全局禁止项、角色白黑名单、后台白名单及现有权限系统。子 Agent 不得成功创建嵌套 Agent，也不得管理同级后台任务。
- F13：定义式 Agent 的可见工具必须经过角色限制并移除 `Agent`、`Task`；Fork 式必须保持父工具定义和顺序不变，但对 `Agent`、`Task` 及其他禁用工具的调用在运行时返回结构化失败。
- F14：后台工具白名单由应用配置统一声明，默认仅允许 `read_file`、`find_files`、`search_code`、`read_git_changes`。配置可增加其他工具，但不能放开全局禁止项，且仍受角色限制和权限系统约束。
- F15：定义式 Agent 默认前台等待 30 秒且可配置。期限内完成时 `Agent` 直接返回结果与用量；超时后任务不中断并自动转后台，返回任务 ID。`background=true` 立即转后台；Fork 始终立即进入后台。
- F16：当前台等待定义式 Agent 时，用户可按 `Ctrl+B` 手动切到后台；该操作不得取消或重启任务。
- F17：后台管理器必须追踪任务 ID、所属主会话、类型、角色、状态、时间、最终结果、失败原因和 Token 用量。
- F18：系统默认最多并发运行 4 个子 Agent 并允许配置；超额任务进入最大 32 项、可配置的 FIFO 队列。队列满时结构化拒绝新任务；排队时间计入前台超时。
- F19：后台任务完成后必须立即显示终端通知，并把任务 ID、状态、最终结果和 Token 用量写入所属主对话的待处理收件箱。收件箱只在两次模型请求之间安全注入，且不得自动唤醒空闲主 Agent。
- F20：系统必须向主 Agent 提供 schema 稳定的 `Task` 工具，支持列出任务、读取任务、有限等待和取消任务；只能访问当前主会话所属任务。
- F21：系统必须提供 `/tasks` 命令供用户查看当前主会话的任务摘要。`Task wait` 超时只报告运行状态，不改变任务前后台属性。
- F22：`/new` 必须取消旧会话全部排队或运行中的子 Agent，并清空尚未注入的结果；CLI 正常退出必须取消全部后台任务、进行有界等待，然后关闭共享基础设施。
- F23：后台任务和结果不跨进程恢复。已经注入并持久化到主历史的结果在恢复会话后只作为普通历史内容存在，不恢复任务对象。
- F24：`Agent` 工具返回必须统一包含任务 ID、类型和状态；同步完成时还包含最终结果与用量，后台任务稍后通过收件箱和 `Task` 工具提供结果。

## 非功能需求

- N1：`Agent` 与 `Task` 的名称、参数 schema 和工具顺序不得因角色数量、任务状态、运行模式或热更新而变化。
- N2：Fork 子 Agent 的首次 Provider 请求在子任务追加点之前，必须与父请求快照保持序列化一致；系统必须保留并汇总 Provider 返回的 cache read、cache creation 等可用指标。
- N3：任务状态转换、收件箱投递、并发计数、FIFO 出队和取消操作必须线程安全；每个任务只能产生一个终态和至多一次收件箱通知。
- N4：单个角色解析失败、子 Agent 失败、任务取消、通知失败或用量字段缺失不得导致主 Agent、其他子 Agent 或后台管理器崩溃。
- N5：角色来源、路径、错误字段和覆盖关系必须产生可定位诊断；诊断不得泄露提示正文、工具参数、凭据或其他敏感值。
- N6：子 Agent 的权限决策和临时授权必须可按任务追踪；任务摘要不得展示敏感工具参数或权限目标内容。
- N7：子 Agent 的消息和中间工具轨迹不得进入主消息历史；主历史只接收规范化的同步结果或后台收件箱结果。
- N8：任务结果和用量必须有界展示，超大内容继续遵守现有上下文外置与压缩机制，不能无界注入主上下文。
- N9：后台并发、排队、前台超时、有限等待和退出收尾必须具有可配置且有界的时间或数量限制，不得无限阻塞 CLI。
- N10：角色热更新、任务创建、状态查询和通知不得要求重新启动进程。
- N11：现有普通 Agent Loop、Skills、Hooks、MCP、权限、会话恢复、上下文管理、Plan/Do 模式及内置工具行为必须保持兼容。
- N12：实现必须支持项目当前声明的 Python 3.10 及以上版本，并通过确定性单元测试和端到端测试验证并发及生命周期行为。

## 不做的事

- 不为子 Agent 创建独立 Worktree、分支、容器、进程级文件系统或工作区快照。
- 不实现多个 Agent 的团队、层级、互相通信、共享计划、任务依赖图或自动编排。
- 不允许子 Agent 创建孙 Agent，也不允许其查询、等待或取消同级任务。
- 不持久化后台任务对象、队列、运行状态、未投递结果或独立权限记录；进程退出或崩溃后不恢复。
- 不实现远程任务执行、跨设备同步、守护进程或 CLI 退出后继续运行。
- 不实现插件发现、插件安装或插件生命周期；本阶段只接收外部注入的插件 Agent 定义目录。
- 不实现动态模型路由、自动选择模型档位、跨 Provider Fork 或硬编码具体 Claude 模型 ID。
- 不保证 Provider 一定命中 prompt cache；本阶段只保证 Fork 前缀稳定，并记录 Provider 实际返回的缓存指标。
- 不让后台完成通知自动触发新的主模型请求。
- 不新增交互式子 Agent 审批、子 Agent 追问用户或将前台任务重新附着为实时交互界面。
- 不将角色系统与现有 Skill 定义合并，也不改变 Skill 的加载、激活和独立执行语义。
- 不新增任意历史会话选择、跨主会话任务访问或跨会话结果投递。

## 验收标准

- AC1：无论角色增删、任务状态、权限模式或主 Agent 模式如何变化，主请求中的 `Agent` 和 `Task` 工具名称、schema 与顺序保持不变；角色变化只影响工具说明中的可用角色信息。（覆盖 F1、F20、N1）
- AC2：定义式请求缺少角色、角色不存在、`prompt` 为空或参数组合非法时，返回可定位的结构化错误且不创建任务；合法请求从空白历史和指定角色提示开始执行。（覆盖 F1、F2、F4）
- AC3：Fork 请求禁止指定角色并始终立即返回后台任务 ID。其首次 Provider 请求在追加子任务之前，与触发工具调用前的父请求 system、消息、当前用户请求、工具定义和顺序一致，且不含父 Assistant 在途输出或本次工具调用。（覆盖 F1、F2、F3、N2）
- AC4：Fork 运行后产生的消息、工具调用和结果不会修改父快照；Provider 提供缓存创建或读取指标时，任务用量能展示并正确汇总这些指标。（覆盖 F3、F8、N2）
- AC5：合法的 Markdown 角色定义能够加载其名称、用途、工具白名单、工具黑名单、模型档位、最大轮次、权限模式和正文提示；字段缺失、类型错误、未知值或空正文只使对应定义失效并产生诊断。（覆盖 F4、N4、N5）
- AC6：项目、用户、内置和注入插件目录中的不同角色均可用；同名时按“项目 > 用户 > 内置 > 插件”选择，多个插件同名时先注册者生效并产生覆盖诊断。（覆盖 F5）
- AC7：新增、修改或删除角色后，无需重启即可影响下一次主请求和之后创建的任务；已经创建的任务继续使用原快照。一个非法角色不会阻止其他角色或主 Agent 工作。（覆盖 F6、N4、N10）
- AC8：`inherit` 使用主 Agent 当前模型；已配置的 `haiku`、`sonnet`、`opus` 映射使用对应具体模型；缺少映射时角色无效并产生诊断，且代码行为不依赖硬编码的 Provider 模型 ID。（覆盖 F7）
- AC9：父子 Agent 执行后可以观察到各自独立的消息、临时权限授权、文件读取缓存和 Token 用量；子任务中间消息及工具轨迹不会进入主历史，而 LLM、Hook 和同一工作区文件系统仍可复用。（覆盖 F8、F9、N6、N7）
- AC10：子 Agent 在模型持续请求工具时继续运行，在模型停止请求工具时自然完成；达到角色最大轮次、被取消或发生错误时进入相应唯一终态，不等待用户交互。（覆盖 F10、N3）
- AC11：子 Agent 遇到需人工批准的操作时不显示审批界面，而收到结构化拒绝并可继续下一轮；其临时授权与权限决策按任务独立追踪。角色只能使用 `inherit`、`default` 或 `strict`，绕过模式定义无效。（覆盖 F11、N6）
- AC12：定义式 Agent 只看到同时通过全局规则和角色白黑名单的工具，并始终看不到 `Agent` 与 `Task`；白名单不能授予原本不存在或无权使用的工具。（覆盖 F12、F13）
- AC13：Fork 首次请求仍保留父工具定义和顺序，但调用 `Agent`、`Task` 或其他运行时禁止工具时，只得到结构化拒绝，不创建孙 Agent、访问同级任务或执行被禁操作。（覆盖 F12、F13、N2）
- AC14：未配置后台白名单时，后台任务只能成功调用四个默认只读工具；配置增加其他工具后，只有同时通过角色限制、后台白名单和现有权限系统的调用才能执行，全局禁止项无法被配置放开。（覆盖 F12、F14）
- AC15：定义式任务在默认或配置的前台期限内完成时，`Agent` 直接返回任务 ID、类型、完成状态、最终结果和用量；显式后台立即返回运行状态；前台超时后同一任务继续后台运行，没有取消、重启或重复执行。（覆盖 F15、F24、N9）
- AC16：等待前台任务时按 `Ctrl+B`，调用立即返回同一任务的后台状态和 ID；任务继续执行并最终只产生一个结果。（覆盖 F16、N3）
- AC17：任务管理器能准确展示任务所属会话、类型、角色、排队、运行、完成、失败或取消状态、时间、结果或失败原因及累计 Token 用量；敏感工具参数和权限目标不出现在摘要中。（覆盖 F17、N6）
- AC18：默认并发 4 个任务时，更多任务按 FIFO 进入最多 32 项的队列；运行槽释放后按顺序启动，队列满时新请求被结构化拒绝且不创建任务。配置值生效，排队时间计入前台超时。（覆盖 F18、N3、N9）
- AC19：后台任务完成、失败或取消后，终端立即显示一次通知，所属主会话收件箱也只收到一次规范化结果；主 Agent 空闲时不产生新的模型请求，下一次请求前才安全注入待处理结果。（覆盖 F19、N3、N7）
- AC20：主 Agent 可通过 `Task list|get|wait|cancel` 管理当前主会话任务；非法参数或其他会话任务 ID 被结构化拒绝；有限等待超时只返回当前状态，取消操作能结束排队或运行中的任务。（覆盖 F20、N9）
- AC21：用户执行 `/tasks` 能看到当前会话的任务 ID、类型、角色、状态和用量摘要，且该命令不调用模型、不泄露敏感参数，也不改变任务状态。（覆盖 F21、N6）
- AC22：执行 `/new` 后，旧会话排队或运行中的任务均进入取消终态，未注入结果被清空，旧任务无法从新会话访问；已运行工具造成的文件改动不回滚。（覆盖 F22）
- AC23：CLI 正常退出会取消全部任务并在有界时间内等待收尾，然后只关闭一次共享基础设施；单个任务拒绝取消或收尾失败不会使退出无限阻塞。（覆盖 F22、N4、N9）
- AC24：进程重启后不会恢复任务、队列、未投递结果或独立权限记录；已经注入并持久化的结果只作为普通主历史恢复，不重新创建任务或重复通知。（覆盖 F23）
- AC25：超大子 Agent 结果按现有上下文边界进行有界展示、外置或压缩，不会把无界内容注入主请求；完整任务状态仍可查询。（覆盖 F24、N8）
- AC26：角色解析失败、单个任务异常、Hook 异常、通知失败、Token 字段缺失或并发取消竞争不会导致主 Agent 及其他任务崩溃；每个任务最终只有一个终态。（覆盖 N3、N4、N5）
- AC27：普通对话、Skills、Hooks、MCP、权限、会话恢复、上下文管理、Plan/Do 模式和现有工具的回归测试通过；项目在 Python 3.10 及以上版本可运行。（覆盖 N11、N12）
- AC28：端到端场景中，主 Agent 先启动一个可同步完成的定义式任务，再启动一个强制后台的 Fork 任务；两者按各自工具与权限边界执行，Fork 保持父请求前缀，后台结果经通知和收件箱返回，`Task` 可查询用量，主历史不含任一任务的中间轨迹。
- AC29：端到端生命周期场景中，定义式任务分别通过显式指定、前台超时和 `Ctrl+B` 三种方式进入后台；任务均不重启且只通知一次，随后 `/new` 或退出能在有界时间内取消和清理剩余任务。
