# Sub-Agent Worktree Isolation Spec

## 背景

MewCode 已支持定义式与 Fork 式子 Agent，但当前所有子 Agent 与主 Agent 共用同一工作目录。并行修改文件时，不同 Agent 会看到并影响彼此的未提交状态，存在覆盖修改、污染缓存和错误判断 Git 状态的风险。

本阶段为声明隔离需求的定义式子 Agent 提供 Git Worktree 工作区。每个隔离任务从主仓库当前 `HEAD` 建立独立目录和分支，并在任务生命周期内始终使用该目录。Fork 式子 Agent 继续共享主工作区。

## 目标

- 让多个隔离子 Agent 与主 Agent 在同一 Git 仓库内安全并行修改文件。
- 提供可恢复、可初始化、可保护性退出和可安全回收的 Worktree 完整生命周期。
- 确保所有工具、指令和路径相关状态按绝对工作目录隔离。
- 在保留有价值改动的前提下，自动回收无变更或满足安全条件的过期临时工作区。

## 功能需求

- F1：只有定义式子 Agent 可以声明 Worktree 隔离。角色 frontmatter 的 `isolation: worktree` 表示需要独立工作区；未声明时沿用共享主工作区。Fork 式子 Agent 不支持 Worktree 隔离。
- F2：每个隔离任务必须拥有独立目录和独立分支，共享原仓库的 Git 对象。目录位于仓库内明确忽略、不参与版本控制的专用根目录下。
- F3：Worktree 标识必须由系统根据受信任的任务信息生成，不接受 LLM 自定义路径。底层生命周期仍必须严格校验标识：限制字符集、分段长度和总长度；允许 `/` 表示嵌套；拒绝空段、`.`、`..`、绝对路径、反斜杠以及任何逃离专用根目录的结果。
- F4：创建 Worktree 时以主仓库调用时的当前 `HEAD` 为唯一代码基线，不复制或暂存主工作区中的未提交修改。创建结果必须记录仓库、任务、基线、分支和目录身份，供恢复与清理验证。
- F5：创建过程必须避免覆盖已有目录、已有分支或其他任务的 Worktree。任一步骤失败时，不得向子 Agent 暴露半初始化工作区，并应安全回滚本次新建的可回滚资源。
- F6：目标目录已存在时进入快速恢复流程。恢复流程只能通过只读文件系统检查确认该目录由本系统创建，并且仓库、任务、分支和目录身份完全匹配；该路径不得调用 Git、覆盖文件或修复不确定状态。任一检查失败都必须拒绝恢复。
- F7：进入隔离环境不允许改变进程级当前目录。系统必须为该任务创建绑定独立绝对工作目录的执行上下文，并把路径及隔离边界说明注入子 Agent。
- F8：隔离任务的每次工具调用都必须显式接收该任务的工作目录。文件访问、搜索、命令、Git 状态和其他路径相关操作均以此目录为边界，不得隐式退回主工作区。
- F9：文件内容、系统提示词、项目指令和记忆等路径相关缓存，必须以规范化绝对路径作为身份的一部分。相同相对路径位于不同 Worktree 时必须形成不同缓存项；进入或退出 Worktree 不依赖全局清缓存来保证正确性。
- F10：Worktree 创建或成功恢复后、子 Agent 开始运行前，系统必须执行幂等的环境初始化。初始化规则由项目配置声明，并提供适合当前项目的安全默认规则；配置只接受经过安全校验的工作区相对路径。
- F11：环境初始化必须支持复制本地配置文件。复制源来自主工作区，目标保持在 Worktree 对应相对位置；不得跟随越界符号链接、复制专用 Worktree 根目录或在诊断中泄露配置内容。可选源缺失时跳过并记录诊断，必需源缺失时阻止任务启动。
- F12：环境初始化必须支持为大型依赖目录建立软链接。链接源必须是配置允许且验证通过的主工作区路径，链接目标必须位于当前 Worktree 内；已有冲突目标、循环链接或边界不明时拒绝操作，不得覆盖现有内容。
- F13：系统必须为子 Worktree 配置独立生效的 Git hooks。该配置不得修改主工作区或其他 Worktree 的 hooks 行为；hooks 路径缺失、越界或配置失败时按规则的重要性决定跳过并诊断或阻止启动。
- F14：系统必须支持按配置补齐被 Git 忽略但运行所需的文件或目录。补齐规则必须明确来源、目标和复制方式，并遵守与本地配置复制相同的路径、覆盖和秘密保护约束。
- F15：环境初始化必须可重复执行。快速恢复时，已满足规则的项目保持不变；存在与规则不一致的目标时不得静默覆盖。初始化失败不得启动子 Agent，并应保留足够的脱敏诊断供用户定位。
- F16：无论子 Agent 正常完成、失败或被取消，系统都必须退出其隔离执行上下文，并检查相对创建基线的工作树和提交状态。任务结束不得因自动清理而丢失文件修改或提交。受管初始化生成的忽略文件和软链接不计为业务变更。
- F17：任务结束时，仅当 Worktree 没有已跟踪修改、没有未忽略的未跟踪文件且没有新增 commit 时，系统才自动删除其目录、Worktree 注册和临时分支。存在上述文件变化或新增 commit 时必须保留，并向主 Agent 返回目录、分支、基线和保留原因，供上层决定后续合并或推送。
- F18：内部生命周期必须支持对指定隔离工作区执行状态检查和删除。删除前必须重新确认目标属于当前仓库的专用 Worktree 根目录、身份记录匹配且确为本系统管理的 Worktree；不得仅凭目录名执行删除。
- F19：默认删除策略必须同时保护未提交修改和未送达提交。存在未提交修改时拒绝删除；存在创建基线之后的新提交，且这些提交尚未合并到当前主分支、也尚未存在于对应远端跟踪分支时，拒绝删除。
- F20：当工作树干净，且相对创建基线没有新增提交，或所有新增提交已经合并到当前主分支或存在于对应远端跟踪分支时，内部删除操作可以安全移除 Worktree 注册、目录和其临时分支。
- F21：需要越过默认保护的强制删除不向 LLM 或子 Agent 暴露。本阶段自动流程不得强制删除含未提交修改，或含有同时未合并且未送达远端跟踪分支的新提交的工作区。
- F22：系统必须记录保留工作区的最后活动时间、生命周期状态和必要身份信息，但不得把该记录作为删除安全性的唯一依据。任务查询结果应能区分已自动删除、因修改保留、因提交保留和清理失败。
- F23：后台清理必须在应用启动时扫描一次，并在运行期间按配置的周期重复扫描；过期阈值和扫描周期必须可配置。一次扫描失败不得阻止应用启动、子 Agent 执行或后续扫描。
- F24：后台清理候选必须依次通过三层过滤：

  1. 路径层：目标的规范化路径位于当前仓库专用 Worktree 根目录内，名称通过同一套安全校验，且不为根目录本身。
  2. 身份层：本地身份记录、目录内身份标记与当前仓库及 Git Worktree 注册信息相互匹配。
  3. 状态层：目标已经过期、没有活动任务占用、工作树干净，并且不存在未合并且未送达远端跟踪分支的新提交。

- F25：只有三层过滤全部通过时，后台清理才能删除目标。任一层不确定、检查失败或状态不满足时必须跳过并记录脱敏原因；不得尝试修复、接管或删除陌生目录。
- F26：后台清理必须处理进程重启前遗留的受管 Worktree，并与正在创建、恢复、运行或退出的任务互斥，避免清理活动目录或与生命周期操作竞争。
- F27：保留下来的 Worktree 不自动合并、不自动变基、不自动推送。主 Agent 或上层流程在处理变更后，可由后续内部生命周期调用重新检查并安全删除。

## 非功能需求

- N1：所有路径输入、身份记录、符号链接和删除目标均按失败关闭原则处理。任何无法证明位于安全边界内的路径都不得创建、复用、覆盖或删除。
- N2：同一仓库中的多个 Worktree 生命周期可以并发执行。创建、恢复、退出和清理必须按目标身份互斥，不能发生分支串用、身份记录覆盖或活动目录被误删。
- N3：生命周期操作必须具备幂等性和崩溃恢复能力。进程异常退出后，系统不得把不完整记录当作有效身份；后续启动可以安全识别完整遗留项，并隔离不确定状态。
- N4：数据保全优先于磁盘回收。Git 状态检查失败、引用关系不明确、远端跟踪信息缺失或删除步骤部分失败时，必须保留现有文件并报告问题。
- N5：Worktree 隔离不得改变进程级当前目录、主工作区文件、主工作区 Git 配置，或其他任务的执行上下文。普通角色和 Fork 式子 Agent 的既有行为保持兼容。
- N6：身份记录、状态结果和错误诊断不得包含本地配置内容、凭据、环境变量值或其他秘密；展示路径时仅提供定位和后续处理所需的信息。
- N7：后台扫描和 Git 状态检查必须有明确的时间与并发边界，不得无限阻塞应用启动、关闭、主 Agent 或子 Agent 执行。
- N8：清理判断只使用本地已有的 Git 引用，不得为确认提交是否送达而自动执行网络访问。缺少可靠远端跟踪引用时，按未送达处理。
- N9：目录复制和软链接初始化必须避免无界递归、符号链接循环及复制 Worktree 专用根目录；大型依赖默认通过软链接复用，不进行重复复制。
- N10：单个隔离任务创建、初始化、退出或清理失败，只影响该任务或目标 Worktree，不得导致其他任务、共享模式子 Agent 或主会话崩溃。
- N11：自动化测试必须使用临时 Git 仓库覆盖路径攻击、并发生命周期、快速恢复、初始化幂等、变更保护、提交保护、进程遗留和三层清理过滤，并通过现有子 Agent、权限、工具、缓存和 CLI 回归测试。
- N12：实现继续支持项目当前声明的 Python 与 Git 运行环境，不引入替代 Git 仓库格式或常驻外部服务。

## 不做的事

- 本阶段不实现 Worktree 之间的合并、变基、挑拣提交或冲突解决策略。
- 本阶段不自动执行 `fetch`、`pull`、`push`，也不创建远端分支。
- 本阶段不把主工作区未提交修改复制、暂存或提交到隔离 Worktree。
- 本阶段不实现跨 Worktree 的实时文件同步、缓存同步或代码广播。
- 本阶段不实现多 Agent 团队编排、任务依赖图、调度策略或结果合并。
- 本阶段不为 Fork 式子 Agent 提供 Worktree 隔离。
- 本阶段不提供面向用户或 LLM 的 Worktree 创建、进入、删除 CLI 或工具接口。
- 本阶段不允许 LLM 指定 Worktree 路径、分支名或绕过删除保护。
- 本阶段不提供容器、独立进程文件系统或非 Git 工作区快照。
- 本阶段不接管、修复或删除用户手工创建及身份不明确的 Worktree 或目录。
- 本阶段不自动清理仍有未提交修改、未合并且未送达提交的工作区，无论其已过期多久。
- 本阶段环境初始化不执行任意项目脚本、依赖安装或构建命令，只执行已声明的复制、软链接、Git hooks 配置和忽略文件补齐规则。

## 验收标准

- AC1：未声明 `isolation` 的定义式角色继续使用主工作区；声明 `isolation: worktree` 的定义式角色使用独立工作区；非法值导致该角色定义失效；Fork 式子 Agent 仍使用主工作区。（覆盖 F1）
- AC2：同时启动两个 Worktree 隔离任务后，两者具有不同的绝对目录和临时分支；目录均位于仓库内的专用忽略根目录，Git 对象仍与主仓库共享，专用目录不会出现在待提交文件中。（覆盖 F2）
- AC3：安全的单段和多段标识可以解析到专用根目录内；包含空段、`.`、`..`、绝对路径、反斜杠、非法字符、超长分段或超长总长度的标识均被拒绝。符号链接或规范化后逃离根目录的路径同样被拒绝。（覆盖 F3、N1）
- AC4：主工作区存在已跟踪修改和未跟踪文件时创建隔离任务，子 Worktree 的内容仍与创建时 `HEAD` 一致，不包含这些未提交内容；身份状态准确记录创建基线。（覆盖 F4）
- AC5：目标目录、分支或任务身份发生冲突时创建失败，不覆盖既有内容；在各创建步骤注入失败后，子 Agent 不会启动，且本次产生的临时资源被回滚或被明确标记为不完整、不可恢复使用。（覆盖 F5、N3）
- AC6：目标目录已存在且仓库、任务、分支、基线和身份标记完全匹配时，可仅通过文件系统只读检查恢复；恢复期间即使 Git 命令被设置为不可调用也能成功。任一字段不匹配、标记缺失、文件不可读或目录是陌生目录时均拒绝恢复，且目录内容不变。（覆盖 F6）
- AC7：隔离任务进入、执行和退出前后的进程当前目录保持不变；子 Agent 的环境说明包含其绝对工作目录、主工作区边界和禁止跨目录操作的说明。（覆盖 F7、N5）
- AC8：在隔离任务中执行文件读取、写入、编辑、搜索、命令和 Git 查询时，所有相对路径都解析到该任务的 Worktree；主工作区的同名文件不被读取或修改，工具执行不得隐式退回主目录。（覆盖 F8）
- AC9：两个 Worktree 在相同相对路径保存不同内容、项目指令和记忆时，各任务得到各自目录的数据；文件内容、系统提示词、项目指令和记忆缓存不会交叉命中，切换任务时无须清空全局缓存。（覆盖 F9）
- AC10：合法的初始化配置和安全默认规则可加载；绝对路径、路径遍历、未知字段、类型错误、冲突规则和指向专用 Worktree 根目录的规则在创建任何文件前被拒绝，并给出对应配置位置。（覆盖 F10）
- AC11：配置声明的本地文件可以从主工作区复制到 Worktree 对应位置；可选源缺失时任务继续并产生脱敏诊断，必需源缺失时任务不启动。越界符号链接、目录递归逃逸和配置内容均不会进入诊断。（覆盖 F11、N6）
- AC12：合法的大型依赖目录在 Worktree 内形成指向已验证主工作区源的软链接，不发生完整复制；目标已存在且不匹配、源越界、循环链接或源类型错误时不覆盖目标并拒绝该规则。（覆盖 F12、N9）
- AC13：子 Worktree 的 Git hooks 按配置生效，主工作区和另一个 Worktree 的 hooks 配置保持不变；可选 hooks 源缺失时产生诊断，必需规则失败时子 Agent 不启动。（覆盖 F13）
- AC14：被 Git 忽略但运行需要的文件和目录可按声明补齐，并保持忽略状态；其复制、链接、缺失源和冲突行为遵守相同的路径与秘密保护规则。（覆盖 F14）
- AC15：对同一已恢复 Worktree 重复运行初始化，不会重复复制、改变正确链接或破坏已有内容；目标与规则冲突时明确失败，不进行静默覆盖，子 Agent 不在半初始化环境中运行。（覆盖 F15）
- AC16：子 Agent 正常完成、执行失败和被取消三种情况下，系统都会退出隔离上下文并检查 Git 工作树与提交状态；检查失败时保留目录。受管初始化生成的忽略文件和软链接不计为业务变更。（覆盖 F16、N4）
- AC17：工作树没有已跟踪修改、没有未忽略的未跟踪文件且没有新增 commit 时，任务完成后自动删除 Worktree 注册、目录和临时分支，并将任务状态标记为已自动清理。（覆盖 F17）
- AC18：存在已跟踪修改或未忽略的未跟踪文件时，任务完成后保留 Worktree；结果向主 Agent 提供绝对目录、临时分支、创建基线和“存在未提交修改”的保留原因。（覆盖 F17、F19）
- AC19：工作树干净但存在创建基线之后的新 commit 时，未合并且未出现在对应远端跟踪分支的提交阻止删除；提交已并入当前主分支或已存在于可靠的对应远端跟踪分支后，重新检查允许删除。检查过程不执行网络访问。（覆盖 F19、F20、N8）
- AC20：内部删除面对目录名相同但身份不匹配、路径越界、Git Worktree 注册不匹配或状态不确定的目标时拒绝操作；正常自动流程和子 Agent 可见工具中不存在绕过保护的强制删除入口。（覆盖 F18、F21）
- AC21：任务查询能够区分正在使用、已自动删除、因未提交修改保留、因新增提交保留和清理失败，并显示必要的脱敏身份与最后活动时间。（覆盖 F22）
- AC22：应用启动时会发现重启前遗留的受管候选；运行期间按配置周期再次扫描，且只选择超过配置阈值的目标。单次扫描失败不会阻止启动、当前任务或下一次扫描。（覆盖 F23）
- AC23：路径层过滤分别拒绝专用根目录本身、根目录外路径、非法名称、规范化逃逸和符号链接逃逸目标，且不对这些目标调用删除操作。（覆盖 F24）
- AC24：身份层过滤分别拒绝身份记录缺失或损坏、目录标记不匹配、仓库身份不匹配、分支不匹配和 Git Worktree 注册不匹配的目标；陌生目录保持原样。（覆盖 F24）
- AC25：状态层过滤分别拒绝未过期、仍有活动任务占用、有已跟踪修改、有未忽略未跟踪文件、有未合并且未送达提交，以及 Git 状态无法可靠确定的目标。（覆盖 F24）
- AC26：只有路径、身份和状态三层过滤全部通过的目标才会被后台删除；任一检查失败只产生脱敏跳过原因，不触发接管、修复或部分删除。（覆盖 F25）
- AC27：后台清理与同一目标的创建、恢复、运行和退出同时发生时，只有一个生命周期操作能够持有该目标；活动任务不会被清理，重启前遗留的安全目标仍可在后续扫描中删除。（覆盖 F26、N2）
- AC28：保留 Worktree 后，系统不会自动合并、变基、挑拣、同步、fetch、push 或创建远端分支；上层完成 Git 处理后，内部生命周期可以重新检查并按保护规则清理。（覆盖 F27）
- AC29：在身份记录写入、环境初始化、Git 状态检查和删除步骤分别模拟进程中断后，重新启动不会把不完整状态误判为可恢复或可删除；仍存在的用户文件不会丢失。（覆盖 N3、N4）
- AC30：单个隔离任务在创建、初始化、运行、退出或清理阶段失败时，主 Agent、普通共享模式子 Agent 及其他隔离任务仍能继续执行；所有错误均不泄露配置内容或凭据。（覆盖 N6、N10）
- AC31：端到端场景中，主 Agent 与两个隔离定义式子 Agent 并行修改相同相对路径，各自只看到自己的内容；一个无业务变更的任务自动清理，一个有未提交修改的任务保留，一个有未送达 commit 的任务保留，处理提交后重新检查可安全删除。（覆盖 F1–F27、N1–N12）
- AC32：现有定义式 Agent、Fork Agent、工具权限、Hooks、任务前后台执行、缓存、项目指令、记忆、会话恢复和 CLI 回归测试通过，项目支持的 Python 与 Git 环境可以运行完整测试套件。（覆盖 N5、N11、N12）
- AC33：Git 状态检查或后台扫描持续无响应时，操作会在配置或系统规定的时间边界内结束；应用仍可关闭，主 Agent、其他子 Agent 和后续扫描不被无限阻塞。（覆盖 N7）
